# 穴馬予測AI - JRA-VAN × LightGBM

JRA-VAN Data Labから取得した競馬データを利用し、  
**人気薄の馬（穴馬）の中から3着以内に入る可能性が高い馬を予測するシステム**です。

C#でJRA-VANからデータを取得してMySQLへ保存し、Pythonで特徴量を生成してLightGBMによる機械学習を行います。

予測結果はJSONとして出力し、WordPress上で公開できる構成にしています。

## C#側の役割

C#では、JRA-VAN Data LabのJV-Linkを利用して競馬データを取得します。

主な処理は以下です。

- JV-Linkの初期化
- レース情報の取得
- 出走馬情報の取得
- レース結果の取得
- リアルタイムオッズの取得
- JRA-VANレコードの解析
- MySQLへの登録・更新

取得したデータはMySQLへ蓄積し、Python側の機械学習処理から利用します。

---

## Python側の役割

PythonではMySQLからデータを取得し、機械学習用の特徴量を生成します。

その後、LightGBMを利用して各馬の3着以内確率を予測します。

処理の流れは以下です。

```text
MySQL
  ↓
学習データ取得
  ↓
特徴量生成
  ↓
Train / Test 分割
  ↓
LightGBM学習
  ↓
予測
  ↓
穴馬候補抽出
  ↓
JSON出力
```

---

## 主な特徴量

現在は、馬の過去成績・適性・前走からの変化などを中心に特徴量を作成しています。

### 基本情報

- 馬番
- 枠番
- 負担重量
- 馬体重
- 馬体重増減
- 距離
- レース番号

### 過去成績

- 前走着順
- 前走人気
- 過去3走平均着順
- 過去3走平均人気
- 過去3走3着内率
- 過去5走平均着順
- 過去5走平均人気
- 過去5走3着内率

### 適性

- 同距離3着内率
- 競馬場別3着内率
- 競馬場別出走数
- 芝・ダート別3着内率
- 芝・ダート別出走数

### 前走からの変化

- 前走からの日数
- 距離変化
- 負担重量変化

## モデル

モデルには **LightGBM** を使用しています。

競馬データのような表形式データに対して扱いやすく、特徴量重要度も確認できるため採用しました。

目的変数は、

```text
3着以内 = 1
4着以下 = 0
```

としています。

単純に「強い馬」を予測するのではなく、人気と予測値を組み合わせて、  
**市場評価より好走可能性が高い馬を探すこと**を目的としています。

---

## 穴馬の抽出

現在は主に、

```text
人気順位 >= 5
```

の馬を穴馬候補としています。

その中からLightGBMの予測値が一定以上の馬だけを抽出します。

例：

```text
人気順位 >= 5
Prediction >= 0.30
```

予測値の閾値については固定値だけで評価せず、バックテストによって比較しています。

---

## バックテスト

学習期間と評価期間を分離し、未来の情報が学習データへ混入しないようにしています。

過去成績系の特徴量についても、現在のレース結果を特徴量へ含めないよう `shift()` を利用しています。

人気薄全体とAIが抽出した馬の3着内率を比較し、モデルの有効性を確認しています。

現在の検証では、5番人気以下全体の3着内率がおよそ11%台であるのに対し、AIで一定条件まで絞った候補では17%前後まで上昇するケースを確認しています。

ただし、競馬予測には期間・開催条件による変動があるため、単月の結果ではなく複数期間でバックテストしています。

## 設計上意識した点

### 未来情報の混入防止

機械学習ではデータリークを防ぐため、過去成績の特徴量生成時に現在レースの結果を利用しないようにしています。

### C#とPythonの責務分離

```text
C#
→ JRA-VANとの接続・データ取得・DB保存

Python
→ データ分析・特徴量生成・機械学習・予測
```

と役割を分けています。

### 秘密情報の分離

DB接続情報などはソースコードへ直接保存せず、環境変数から取得できる構成にしています。

GitHubには認証情報・利用キー等を含めていません。
